# ADR-001: аккаунты и администрирование

**Статус:** принято для реализации; подключение облачного проекта ожидается.
**Дата:** 2026-10-24.
**Основание:** владелец выбрал подготовку подключения Supabase.

## Контекст

«Якорь» — статический сайт на GitHub Pages. Пользователю нужны регистрация, вход по email и паролю, восстановление пароля, профиль и администрирование общей библиотеки. GitHub Pages не выполняет серверный код. Содержимое личных книг уже хранится в IndexedDB.

## Решение

Оставить сайт на GitHub Pages, добавить Supabase Auth и PostgreSQL с Row Level Security. Официальный JavaScript SDK хранится в репозитории локальным собранным модулем и загружается только при настроенном подключении. Пароли проверяет Auth; сайт не создаёт собственную базу паролей. В клиентском конфиге допускаются только URL проекта и публичный publishable/anon key.

Читатель управляет собственным именем профиля. Отдельная серверная таблица определяет администраторов; пользовательские metadata и интерфейсные флаги прав не дают. Первый администратор назначается владельцем базы после подтверждения email. Администратор редактирует общие книги, публикует и скрывает их, просматривает пользователей. Удаление аккаунтов и назначение ролей через публичный интерфейс в этот этап не входят.

После подключения общая полка поступает из Supabase; её начальное наполнение — 16 существующих классических произведений. Скрытие убирает книгу с общей полки. Уже загруженная пользователем копия остаётся локально. Личные импорты и место чтения сохраняются в браузере. Аккаунт не включает облачную синхронизацию личных книг.

Без облачного конфига читалка работает в гостевом режиме. Экран аккаунта сообщает о неподключённом сервисе и не собирает email или пароль. Этот режим не выдаётся за действующую авторизацию.

## Рассмотренные варианты

| Вариант | Преимущества | Последствия |
| --- | --- | --- |
| Supabase | Подходит к статическому сайту, управляемый Auth, PostgreSQL RLS | Нужен отдельный проект, настройки почты и контроль его лимитов |
| Firebase | Управляемая авторизация и база | Другие правила доступа и модель данных; не выбран владельцем |
| Собственный сервер | Полный контроль над хранением и сессиями | Нужны серверный хостинг, почта, обновления и сопровождение |

## Проверка и ввод в работу

Клиентские тесты проверяют состояния аккаунта и ошибки; отдельные SQL-тесты проверяют реальные ограничения PostgreSQL от имени anon, читателей и администратора. Браузерные сценарии интерфейса используют явно изолированный тестовый клиент. Они не подтверждают доставку писем или работу конкретного облачного проекта.

Ввод в работу: создать Supabase-проект, применить миграцию, включить подтверждение email и настроить redirect/почту, перенести общую полку, записать публичный конфиг, зарегистрировать и подтвердить владельца, назначить серверную роль и проверить вход на настоящем сайте.
